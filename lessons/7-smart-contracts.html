Lesson 7: Smart contracts

A smart contract is a small program stored on the blockchain. Anyone can use it, it follows its rules exactly, and nobody can change or stop it.

Words in this lesson

Read these first. Each word is explained here before the lesson uses it. All words: glossary.

Program (code)
Step-by-step instructions that a computer follows exactly.
Smart contract
A program stored on the blockchain. Anyone can use it, and nobody can change it.
Solidity
The programming language most Ethereum smart contracts are written in.
Deploy
Put a contract on the blockchain. After that its code can't be changed.
Contract address
Where a deployed contract lives, like a wallet address. It can hold ETH.
Function
One action a contract offers, like deposit() or withdraw().
Call
Use a function, for example "call withdraw()".
State
The information a contract remembers, like who its owner is and how much ETH it holds.
Owner
In our example, the account that deployed the contract. The contract's rules give it special rights.
Revert
A rule failed, so the whole call is cancelled and nothing changes.

So far the blockchain has only stored payments. Ethereum can also store programs. Once one is on the blockchain, every node runs it the same way and the results are recorded in blocks, just like payments.

Think of a vending machine

A vending machine has no shopkeeper. The rules are built in: put in enough money and choose an item → you get the item; not enough money → you get nothing. Nobody can argue with it or bend the rules. A smart contract is a vending machine made of code, living on the blockchain.

Our example: a piggy bank

Its rules: anyone can put ETH in, but only the owner can take it out. Here's the whole contract, written in Solidity, Ethereum's main language. Don't try to memorise the code; just match each part to the rules.

⚠️ Code can't be changed after deploying, and that includes bugs. If a contract has a mistake, it stays there forever, and attackers look for exactly these. That's why real contracts are carefully tested and checked ("audited") before deploying.

Check yourself

    
Account 2 deposits 2 ETH, then calls withdraw(). What happens, and why? Does the piggy bank's balance change?

    
Show answer
      
It's rejected (reverted). The rule require(msg.sender == owner) fails because Account 2 isn't the owner. The whole call is cancelled, so the piggy bank still holds the 2 ETH. On a real network Account 2 would still pay a small fee for the failed attempt, as the playground shows.
