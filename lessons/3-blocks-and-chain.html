Lesson 3: Blocks and the chain

Each block stores the previous block's hash. So changing old data breaks every link after it.

Words in this lesson

Read these first. Each word is explained here before the lesson uses it. All words: glossary.

Block
One page of the ledger: a group of transactions plus a little extra information.
Chain
Blocks kept in order, each one pointing back to the block before it.
Prev hash
The previous block's hash, written inside each block. It is the link of the chain.
Genesis block
The very first block. It has no block before it.
Tampering
Secretly changing data that is already recorded.

The record book is split into pages called blocks. Each block holds four things:

  1. Its number: block 1, 2, 3…
  2. Data: the transactions, like "A pays B 50"
  3. Prev: the hash of the block before it
  4. Hash: its own fingerprint, computed from all of the above

Point 3 is the key idea: each block writes down the fingerprint of the block before it. That link is the "chain" in blockchain.

Hashes are shortened to 4 characters here to keep the picture readable. Real ones are 64.

What if someone changes an old block?

Say a hacker changes Block 1 from "A pays B 50" to "A pays B 500":

  1. Block 1's data changed, so its hash changes. It's no longer 8a1f.
  2. Block 2 still says Prev: 8a1f, so the link is broken ❌.
  3. Everyone can see exactly where the tampering is: the first broken link.

Try it: be the hacker

Real hashes, computed live. Edit any block's data and watch which blocks turn red.

Try changing 50 to 500 in block 1.
  1. Change 50 to 500 in block 1. Block 1 turns red (contents changed) and block 2 turns red (broken link). Block 3 stays green.
  2. Click Reset, then edit block 3. Only block 3 turns red, because links only point forward.
  3. Edit block 1 again and click Hacker: recompute every link. Everything is green again 😮 What stops a real hacker from doing this? → Lesson 5.

Check yourself

Someone changes block 2 in a chain of 100 blocks. Which blocks show a problem? What would the hacker have to do to hide it?

Show answer

Block 2 (contents changed) and block 3 (its link to block 2 breaks). Block 1 is fine, because links only point forward.

To hide it, the hacker must fix block 3's link, which changes block 3's hash and breaks block 4, and so on. They'd have to redo every block from 2 to 100. The older a block is, the harder it is to change.
